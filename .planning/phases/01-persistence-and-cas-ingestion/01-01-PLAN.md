<objective>
Implement relational database persistence via Supabase/PostgreSQL with automatic offline fallback to db.json, and build the CAMS/KFintech Consolidated Account Statement (CAS) statement ingestion parser and endpoint.

Purpose:
Upgrade the data layer from a hackathon prototype to a database-backed, production-grade schema while safeguarding the live demo against offline network failures, and allow realistic user mutual fund / stock statement ingestion.

Output:
- `server/data/schema.sql`: Complete PostgreSQL DDL schema with tables, constraints, and Row-Level Security templates.
- `server/src/lib/supabase.js`: Supabase client factory and query helpers.
- `server/src/lib/store.js`: Updated dual-mode store maintaining backwards-compatible sync/async interface.
- `server/src/lib/casParser.js`: Robust parser for CAMS/KFintech statement extracts.
- `server/src/routes/api.js`: New `/api/upload/cas` route wired to holdings and live alerting.
</objective>

    Extracted fields per holding:

    - `registeredDob`: Investor DOB if present
    - `status`: 'active' | 'inoperative'
